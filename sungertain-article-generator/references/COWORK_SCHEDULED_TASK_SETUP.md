# Cowork定時任務設置指南

## 📅 每日自動生成文章配置

此指南說明如何在Cowork中設置每日09:00自動生成靈芝農場文章。

---

## 🎯 設置目標

| 項目 | 設置 |
|------|------|
| **執行時間** | 每日早上 09:00 (UTC+8 台灣時間) |
| **頻率** | 每天執行一次 |
| **產品** | 根據7天輪轉計劃 |
| **輸出格式** | Word檔案 + JSON (存入Azure SQL) |
| **品質標準** | ≥75/100分 |

---

## 📋 在Cowork中建立定時任務

### 步驟1：開啟Cowork設置

```
1. 開啟Cowork應用
2. 點擊「設置」(設定圖標)
3. 找到「定時任務」或「Scheduled Tasks」
4. 點擊「新建任務」
```

### 步驟2：輸入基本信息

```
任務名稱：三才靈芝農場 - 每日文章生成
描述：每日早上9點自動生成靈芝農場博客文章，包含Meta信息、文章主體和參考資源
```

### 步驟3：設置執行時間

**選擇「定期執行」(Recurring)：**

```
Cron表達式：0 9 * * *

說明：
0   = 分鐘 (00分)
9   = 小時 (09點)
*   = 每天
*   = 每月
*   = 每周的每天

結果 = 每天早上9:00執行
```

**驗證時區：**
```
時區設置：Asia/Taipei (UTC+8)
驗證：下次執行時間應該是今天09:00
```

### 步驟4：輸入Prompt（提示詞）

複製以下內容，貼入Cowork定時任務的「提示詞」欄位：

```markdown
# 三才靈芝農場 - 每日文章自動生成

## 任務目標
根據7天輪轉計劃生成今天的博客文章。

## 今日計劃信息
請根據以下計劃信息自動判斷今天應生成的文章：

7日輪轉計劃：
- Day 1 (5/14)：入門認識 > 靈芝黑木耳露 (瓶) - SKU: FD-WOODEAR-001
- Day 2 (5/15)：選購指南 > 靈芝茶包 (6入) -小 - SKU: FD-TEA-001
- Day 3 (5/16)：選購指南 > 靈芝膠囊 100% (60粒) - SKU: WN-REISHICAP-001
- Day 4 (5/17)：飲食指南 > 靈芝健康咖啡 (5 入) - SKU: FD-COFFEE-001
- Day 5 (5/18)：保存方式 > 靈芝原朵 (小包) - SKU: FD-RAW-001
- Day 6 (5/19)：常見問題 > 靈芝養生膳食 - SKU: FD-SOUP-001
- Day 7 (5/20)：深入認識 > 五倍靈芝粉 - SKU: WN-REISHI-001

## 文章規格

### Meta信息表格（必填）
- SEO標題：40-60字元（包含主要關鍵詞）
- Meta描述：120-160字元（吸引點擊）
- 發佈日期：YYYY-MM-DD格式
- 分類：根據上面的計劃指定
- 推薦產品：完整產品名稱
- 產品SKU：正確的SKU代碼
- 目標受眾：簡要描述

### 文章內容（必填）
- 字數：600-1000字（必須）
- 結構：引言 → 主體 → 結語
- 視點：消費者視點
- 語言：繁體中文、清晰易讀
- 無虛假聲稱：避免誇大或不實

### 參考資源（必填）
- 數量：5-7條（必須）
- URL類型：具體頁面（非首頁）
- 來源級別：至少50%是1-2級來源
- 日期信息：存取日期/發佈日期
- EEAT說明：簡要解釋專業度/權威度

## 執行步驟

1. **計算今天在7天周期中的位置**
   - 基準日期：2026-05-14 (Day 1)
   - 計算距離基準日期的天數
   - 結果 = ((today - 2026-05-14).days % 7) + 1

2. **查詢該天的分類和產品**
   - 使用上面的輪轉計劃表
   - 確保只使用表格中列出的產品
   - 不要編造或替換產品

3. **生成完整Word文檔**
   - 黑藍色表格 (#366092) 包含Meta信息
   - 白色文字、居中對齊
   - 文章內容使用正常格式化
   - 參考資源編號格式：[1], [2], ..., [7]

4. **生成JSON輸出**
   - ArticleID: YYYYMMDD_分類_簡化產品名
   - PublishDate: YYYY-MM-DD
   - Category: 6個分類之一
   - MetaTitle: 40-60字元
   - MetaDescription: 120-160字元
   - ArticleBody: HTML格式
   - References: 5-7個物件，每個包含URL、Title、Authority、EEAT_Explanation
   - DayInCycle: 1-7
   - QualityScore: 根據評分標準計算

5. **品質驗證**
   - 檢查所有字符限制
   - 驗證至少50%的高級來源
   - 確認無虛構產品
   - 計算品質分數（≥75及格）

6. **輸出結果**
   - Word文檔：YYYYMMDD_分類_產品.docx
   - JSON格式用於Azure SQL存儲
   - 如果品質分數 < 75，請重新生成

## 成功標準

✅ 及格分數：≥75/100

評分構成：
- 結構合規 20% (Meta表格、章節、格式)
- 內容品質 30% (字數、相關性、實用性)
- 產品準確 20% (驗證清單、無虛構)
- 參考質量 20% (數量、來源級別、EEAT)
- SEO優化 10% (標題、描述、關鍵詞)

## 禁止清單

❌ 不能使用的產品：
- 靈芝孢子粉 (未驗證)
- 靈芝濃縮液 (未驗證)
- 任何清單外的產品

❌ 不能做的事：
- 編造或虛構產品
- 編造研究或數據
- 提供醫療建議（改為「諮詢專業人士」）
- 超過1000字或少於600字
- 只使用一個來源

## 錯誤處理

如果發生以下情況，請重新嘗試：

1. **品質分數 < 75**
   - 檢查字數是否在600-1000之間
   - 確認参考資源有效且相關
   - 確保無虛假聲稱

2. **參考資源數量不對**
   - 需要5-7條，不多不少
   - 所有URL必須有效
   - 必須包含EEAT解釋

3. **Meta信息長度不符**
   - 標題：40-60字元（含標點）
   - 描述：120-160字元（含標點）
   - 使用字符計數工具驗證

## 完成後

生成完後，請提供：
1. Word檔案下載連結
2. JSON格式的完整輸出（用於存入Azure SQL）
3. 品質分數和詳細評分
4. 任何警告或建議

## 常見問題

**Q: 如果某天執行失敗怎麼辦？**
A: 系統會記錄執行日誌。可以手動重新執行或等待次日自動執行。

**Q: 可以改變執行時間嗎？**
A: 可以。修改Cron表達式：
- 改為08:00：`0 8 * * *`
- 改為18:00：`0 18 * * *`

**Q: 可以跳過某一天嗎？**
A: 可以。暫時關閉定時任務或手動延遲執行。

**Q: 品質分數如何計算？**
A: 見上面的「成功標準」部分。滿分100，≥75及格。
